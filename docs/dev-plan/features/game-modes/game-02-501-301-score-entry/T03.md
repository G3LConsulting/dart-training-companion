# T03 — Frontend: Game State Service (Manages Turns, Scores, Player Switching)

## Metadata
- **Story:** GAME-02
- **Layer:** Frontend (Angular)
- **Status:** Planned
- **Agent:** Angular Developer
- **Depends on:** GAME-01

## What to Build
Create a centralized game state service that manages the complete 501/301 game lifecycle: turn tracking, score calculations, player switching, bust detection, undo functionality, and game completion detection. Service uses RxJS observables for reactive state updates.

## Definition of Done
- [ ] Service exposes observable streams: `gameState$`, `currentPlayer$`, `remainingScore$`, `gameOver$`, `turns$`, `canUndo$`
- [ ] `addTurn(score: number): void` accepts score, validates against bust rules, updates state
- [ ] `getBustDetection(score: number, config: GameConfig): { isBust: boolean; reason: string }` logic implemented
- [ ] Bust detection considers: double-out rule, score < 1, remaining score accuracy
- [ ] `undo(): void` reverts to previous turn state (one level); no-op if no history
- [ ] Player alternation handled automatically for 2-player games
- [ ] `getGameOver(): Observable<boolean>` detects checkout (score = 0 on double)
- [ ] `getTurnCount(): number` and `getRemainingScore(): number` accessors implemented
- [ ] Service maintains immutable state (no mutations)
- [ ] Service initializes from config passed from GAME-01
- [ ] All unit tests pass (standard flow, bust scenarios, undo, player switching, checkout detection)

## Implementation Notes
- Use RxJS BehaviorSubject for state management
- Implement turn history as immutable array
- Bust detection should be pure function for testability
- Consider performance: state updates should not cause unnecessary re-renders
- Service can be reset for new game
- Support hydration from auto-saved state (GAME-08)
