# T01 — API: CreateSessionCommand with Handler and Validator

## Metadata
- **Story:** GAME-04
- **Layer:** Backend (C#)
- **Status:** Planned

## What to Build
Implement CQRS command for saving completed game sessions: CreateSessionCommand, handler, and validator. Command accepts game data (turns, mode, players) and persists to database. Validator ensures data integrity.

## Definition of Done
- [ ] Command class accepts: GameMode, GameType (501/301/Cricket/NumberFocus), PlayerNames (list), GameConfig (json), Turns (list)
- [ ] Handler validates command using FluentValidation
- [ ] Validator checks: at least 1 turn, mode is valid, players count matches config
- [ ] Handler creates GameSession entity with: Id (guid), UserId, CreatedAt, Mode, GameType, Turns, Stats (calculated)
- [ ] Stats calculated: TurnCount, ThreeDartAverage, HighestTurn, TotalScore, Duration
- [ ] Handler saves entity to database via repository
- [ ] Handler returns CommandResult with SessionId and timestamp
- [ ] Endpoint returns 201 Created with Location header (api/sessions/{id})
- [ ] Database transaction ensures data integrity
- [ ] Error handling: returns 400 for validation errors, 500 for server errors
- [ ] API response includes SessionId for tracking
- [ ] All handler tests pass

## Implementation Notes
- Use MediatR for command dispatch
- FluentValidation for input validation
- Entity Framework for persistence
- Calculate stats from turn data (3-dart average = total score / (turns * 3))
- Support both 1-player and 2-player games
- Consider idempotency (check for duplicate sessions within same minute)
