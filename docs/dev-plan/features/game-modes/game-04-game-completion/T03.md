# T03 — Frontend: Session Save Logic (Call CreateSessionCommand API)

## Metadata
- **Story:** GAME-04
- **Layer:** Frontend (Angular)
- **Status:** Planned
- **Agent:** Angular Developer
- **Depends on:** T01 (CreateSessionCommand API), GAME-02 (Game data)

## What to Build
Create API service that calls CreateSessionCommand endpoint to persist completed game sessions. Service handles error handling, offline scenarios (via GAME-08), and user feedback.

## Definition of Done
- [ ] SessionsApiService exposes `saveSession(sessionData: CreateSessionRequest): Observable<CreateSessionResponse>`
- [ ] Service POSTs to `POST /api/sessions` with session data
- [ ] Request includes: mode, gameType, players, turns, gameConfig, timestamp
- [ ] Response includes: SessionId, timestamp, statusCode
- [ ] Service handles 201 (success), 400 (validation error), 500 (server error)
- [ ] Error responses include error message for user feedback
- [ ] Service implements retry logic (3 attempts with exponential backoff)
- [ ] Offline handling: returns error that triggers queue for sync (GAME-08)
- [ ] GameSaveService orchestrates save: calls API, shows loading/success/error toast
- [ ] Loading state: shows "Saving..." notification while request pending
- [ ] Success state: shows "Game saved" with SessionId reference
- [ ] Error state: shows error message with retry option
- [ ] Session ID returned for analytics/tracking
- [ ] All unit tests pass (mocked API, error scenarios)

## Implementation Notes
- Use HttpClient for API calls
- Implement RxJS operators for error handling and retries
- Show Toast/Snackbar notifications for user feedback
- Consider offline queue implementation (GAME-08 sync)
- Timeout: 5 seconds for save request
- Log save errors for debugging
