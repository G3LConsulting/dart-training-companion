## Definition of Done
- [ ] Test: Standard game flow — 2 players marking numbers, alternating turns
- [ ] Test: Mark tracking — marks increment correctly per number (0–3 capped)
- [ ] Test: Number closure — 3 marks closes number for that player
- [ ] Test: Point scoring — marks beyond 3 award 1 point each
- [ ] Test: Point scoring on open numbers only — closed numbers don't score
- [ ] Test: Point scoring verification — example: Player 1 marks T20 4 times = 1 point (3 to close, 1 point)
- [ ] Test: Game completion — all numbers (15–20, Bull) closed by both players ends game
- [ ] Test: Game completion detection — game not over if only one player closed all
- [ ] Test: Player alternation — turns switch between players correctly
- [ ] Test: Undo functionality — reverts to previous turn state
- [ ] Test: Undo disabled when no previous state
- [ ] Test: Undo one level only — multiple undos don't work
- [ ] Test: Turn history preserved for undo
- [ ] Test: Game abandonment — user can end game early
- [ ] Test: Stats calculation — turns and marks recorded correctly
- [ ] Test: Edge case — both players close same number (both get closure)
- [ ] Test: Edge case — player hits number after other player closes it
- [ ] Test: Scoreboard updates reactively as darts added
- [ ] Test: Game initialization from config (player names, mode)
- [ ] All tests pass with >85% code coverage

## Implementation Notes
- Use marble testing for RxJS observables
- Mock services for component tests
- Test various game scenarios: quick wins, long games, multiple closures
- Validate scoreboard state after each operation
- Consider snapshot tests for scoreboard layout
