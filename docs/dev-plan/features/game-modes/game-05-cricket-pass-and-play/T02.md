# T02 — Frontend: Cricket Game State Service

## Metadata
- **Story:** GAME-05
- **Layer:** Frontend (Angular)
- **Status:** Planned

## What to Build
Create Cricket-specific game state service that manages turn state, mark tracking per number per player, point calculation, game completion detection, and undo functionality. Service exposes observables for reactive scoreboard updates.

## Definition of Done
- [ ] Service initializes from game config (player names, target setup)
- [ ] Service exposes observables: `gameState$`, `scoreboard$`, `currentPlayer$`, `gameOver$`, `canUndo$`
- [ ] `addDart(dartOutcome: 'S' | 'D' | 'T' | 'Miss', number: 1-20 | 'Bull'): void` records dart
- [ ] Dart submission collects 3 darts per turn, then processes turn
- [ ] `processTurn(): void` updates marks and calculates points for closed numbers
- [ ] Mark tracking: counts marks per number per player (0–3, then capped)
- [ ] Number closure detection: when player reaches 3 marks on a number
- [ ] Point calculation: only open numbers award points (3 marks = 1 point per mark beyond 3)
- [ ] Player alternation: turn switches to other player after each turn
- [ ] `undo(): void` reverts to previous turn state (one level)
- [ ] `getGameOver(): Observable<boolean>` detects: all numbers closed by both players
- [ ] Scoreboard data structure: { numbers: {}, players: {}, points: {} }
- [ ] Service maintains immutable state
- [ ] Support game abandonment (user end game early)
- [ ] All unit tests pass

## Implementation Notes
- Use RxJS BehaviorSubject for state management
- Implement turn history as immutable array for undo
- Point scoring: marks beyond 3 count as 1 point each (e.g., 4 marks = 1 point, 5 marks = 2 points)
- Both players must close all numbers to end game
- Support hydration from auto-saved state (GAME-08)
