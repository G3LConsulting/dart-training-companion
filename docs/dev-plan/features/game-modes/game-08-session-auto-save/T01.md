# T01 — Frontend: Auto-Save Service (Writes to localStorage After Each Score/Dart)

## Metadata
- **Story:** GAME-08
- **Layer:** Frontend (Angular)
- **Status:** Planned
- **Agent:** Angular Developer
- **Depends on:** GAME-02, GAME-05, GAME-07 (Game state services)

## What to Build
Create auto-save service that persists game state to browser localStorage after every scored turn or dart entry. Service must not add latency to score entry (≤ 100ms total). Supports serialization/deserialization of all game types.

## Files

| File Path | Purpose | Type |
|-----------|---------|------|
| `src/app/core/session/auto-save.service.ts` | Auto-save management service | Service |
| `src/app/core/session/auto-save.service.spec.ts` | Service unit tests | Test |
| `src/app/core/session/session-storage.model.ts` | TypeScript interfaces for stored state | Model |

## Definition of Done
- [ ] Service exposes `saveSession(sessionData: GameSessionState): void`
- [ ] Service serializes state to JSON and writes to localStorage key: `game_session_in_progress`
- [ ] Saved state includes: mode, gameType, config, all turns/darts, currentPlayer, timestamp
- [ ] Auto-save triggered by game state services (observables subscription)
- [ ] Save completes within 100ms (including serialization)
- [ ] Service handles serialization of complex objects (turns, marks, etc.)
- [ ] Service validates data before saving (not null, has turns)
- [ ] Supports multiple game types: 501, 301, Cricket, Number Focus
- [ ] `getSavedSession(): GameSessionState | null` retrieves saved state
- [ ] `clearSavedSession(): void` deletes saved state from localStorage
- [ ] Service checks localStorage quota and handles overflow gracefully
- [ ] Only one session saved at a time (overwrites previous)
- [ ] Timestamp included for resume/recovery logic
- [ ] Performance: save operation non-blocking (consider async/debounce if needed)
- [ ] All unit tests pass

## Implementation Notes
- Use JSON.stringify/parse for serialization (consider compression for large states)
- Debounce auto-save to avoid excessive writes (e.g., 500ms debounce, but still fast enough)
- localStorage limit ~5-10MB; monitor size
- Consider error handling for quota exceeded
- Log auto-saves for debugging (dev mode)
- Can be triggered from game state services via RxJS throttle/debounce
